# รอบวิจัยนโยบายภารกิจ R2

โมเดลตรวจภาพpublic-v4ยังคงรุ่นเดิม รอบใหม่นี้พัฒนานโยบายตัดสินใจเดินเรือด้วยsparse Q-learningจากตัวจำลองR2 ใช้คำสั่งแปดแบบ รวมSTOPและHOLD โดยไม่มีการต่อมอเตอร์จริงและยังไม่มีตัวเชื่อมกับนโยบายบนเว็บไซต์

## รูปแบบโมเดลและการเปรียบเทียบ

`warirak.mission-q-policy.v1` ใช้สถานะเชิงหมวดหมู่220,320แบบ และเก็บเฉพาะแถวที่เคยพบในตารางQ ข้อมูลประกอบด้วยทิศเป้าหมาย/มองไม่เห็น ระยะสามช่วง สิ่งกีดขวางด้านหน้า ความพร้อมHOLD โหมดภารกิจ หมวดความเร็วตามหัวเรือจากข้อมูลวัดจำลอง และคำขอครั้งก่อน ไม่มีตำแหน่งจริงของขยะหรือพิกัดโลกภายในตัวจำลองเป็นข้อมูลเข้าของผู้เรียน ส่วนการคำนวณรางวัลใช้ระยะจริงในโลกจำลองและบันทึกไว้ชัดเจน

เปรียบเทียบกับสองตัวอ้างอิง: นโยบายเดิมที่จับคู่การกระทำกับR2อย่างชัดเจน และกฎที่ใช้ความสามารถHOLD ทั้งตัวอ้างอิงและผู้เรียนใช้ฟิสิกส์ เซนเซอร์จำลอง ตัวกำกับ และขอบเขตคำขอชุดเดียวกัน เมื่อข้อมูลระยะหาย จะคงเพียงเจตนาคำขอเดิมเพื่อให้ตัวกำกับR2ออกWAIT/faultและตัดแรงขับ ไม่ใช้ค่าที่แคชไว้เป็นสิทธิ์เดินเรือ ไม่ล้างประวัติความก้าวหน้าด้วยSTOPที่แทรกขึ้นจากตัวเปรียบเทียบเอง

## แผนที่กำหนดก่อนดูคะแนน

ไฟล์แผนคือ `navigation-mission-r2-experiment-protocol.json` ตัวรันจะบันทึกแผนพร้อมSHA-256ของซอร์ส สัญญาR2 และนโยบายอ้างอิง ก่อนคำนวณvalidationหรือเริ่มฝึก หากซอร์ส/แผนเปลี่ยนจะไม่resumeงานเดิม

ฝึกหนึ่งเส้นทางสูงสุด6,000episodes บนCPUในเครื่อง ผสมnominal25%/stress75% เก็บผู้สมัครที่2,000และ6,000episodesจากเส้นทางเดียวกัน พร้อมcheckpointทุก100episodes ช่วงseedฝึกเริ่ม24,000,000 ส่วนvalidationเริ่ม26,000,000/26,500,000อย่างละ200episodes และtestเริ่ม28,000,000/28,500,000อย่างละ400episodes มีการป้องกันช่วงseedทับกัน

เกณฑ์งานวิจัยมีทั้งสัมบูรณ์และเปรียบเทียบ: ต้องรักษาผลnominalและเพิ่มความสำเร็จstressอย่างน้อย0.02เหนืออ้างอิงที่ดีกว่า โดยเทียบการชนกับอ้างอิงที่ชนต่ำกว่า รวมทั้งผ่านเกณฑ์ความสำเร็จ การชน การหมดเวลา การขอความช่วยเหลือ ความไม่พร้อมของการควบคุม และช่วงรอข้อมูลตามแผน ค่าเกณฑ์งานวิจัยนี้ยังยอมรับข้อจำกัดของตัวจำลอง จึงแยกจากเกณฑ์ความพร้อมใช้งานที่เข้มงวดกว่าในไฟล์เดียวกัน

ทุกepisodeยังคงอยู่ในตัวหาร เมื่อขอความช่วยเหลือจะไม่หยุดตัวจำลองเพื่อซ่อนการลอยไปชน ต้องคำนวณต่อจนชน เก็บสำเร็จ หรือครบ960ขั้น กรณีความหน่วง600มิลลิวินาทีที่เกินอายุคำสั่ง400มิลลิวินาทียังคงอยู่และรายงานความไม่พร้อม ไม่ต่ออายุคำสั่งเพื่อทำคะแนนให้ดีขึ้น

เลือกผู้สมัครจากvalidationเท่านั้น หากไม่มีผู้สมัครผ่านทุกเกณฑ์ จะคงนโยบายที่เผยแพร่และไม่เพิ่มรอบต่อโดยอัตโนมัติ หากผ่านจะจบที่ `candidate_ready_for_review` โดยtestยังปิดอยู่ ต้องทบทวนหลักฐานและความพร้อมก่อนเปิดtestจำลอง ไฟล์นโยบายใหม่ไม่สามารถแทนตารางห้าการกระทำบนเว็บไซต์ได้โดยตรง

## การทำงานต่อจากcheckpoint

จากรากโครงการ:

```sh
node ai/train_navigation_mission.mjs work/navigation-mission-r2-experiment
```

หากงานขัดข้อง ให้ตรวจ `status.json`, log, `failed_phase`, checkpoint และPIDก่อน ใช้คำสั่งต่อไปนี้เฉพาะเมื่อprocessเดิมหยุดแล้ว:

```sh
node ai/train_navigation_mission.mjs work/navigation-mission-r2-experiment --resume
```

ตัวรันมีlockป้องกันงานซ้ำและปฏิเสธการเริ่มงานที่จบแล้ว อ้างอิงสถานะจริง ไม่ใช้phaseเก่าหรือPIDเก่าตัดสินว่าต้องฝึกใหม่ ผลทั้งหมดของรอบนี้เป็นข้อมูลสังเคราะห์ ไม่มีการอ้างความแม่นยำกล้องเรือ ความปลอดภัยภาคสนาม หรือผลควบคุมฮาร์ดแวร์
