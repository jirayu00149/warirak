# กรอบออกแบบการเรียนรู้นโยบายหลังการศึกษากฎ corridor

เอกสารนี้เป็น **แผนออกแบบซอฟต์แวร์ก่อนฝึก** ยังไม่ใช่ protocol ที่อนุญาตให้เริ่มงาน และยังไม่มี neural policy ที่ฝึกใหม่

## สมมติฐานที่ต้องตรวจ

Q-table รุ่นก่อนบีบข้อมูลระยะด้านข้าง/ด้านหลังและการเคลื่อนที่เป็นหมวดหยาบ ขณะที่กฎ corridor แสดงผลดีขึ้นเฉพาะบางฉากจากประวัติระยะและ motion ที่สด สมมติฐานใหม่คือการเรียนรู้ค่าของคำขอที่ยังได้รับอนุญาตจาก features ต่อเนื่องพร้อมประวัติ อาจจัดอันดับการกระทำได้เหมาะสมกว่ากฎ STOP fallback ต้องทดสอบจริงและคงผลล้มเหลวทั้งหมดไว้ ไม่ถือว่ากฎ corridor เป็นผู้สอนที่ถูกต้องเสมอ

## งานที่ต้องเสร็จก่อนเริ่มฝึก

1. ออกแบบ schema และ encoder ที่มีลำดับ features ชัดเจนสำหรับระยะทั้งแปดทิศพร้อม known flags, target ตามข้อมูลสังเกต, motion ตามยาว/ตามขวาง/yaw ที่วัดอย่างอิสระ, อายุข้อมูลจากเวลาเดิม, สถานะตัวกำกับ/ACK, คำขอก่อนหน้า และประวัติแบบจำกัดขนาด ข้อมูลขาดหายต้องมี mask แยกจากค่าศูนย์จริง ห้ามใช้พิกัดโลกหรือข้อมูล diagnostic เป็นอินพุตผู้เรียน และห้ามสร้างความเร็วจากแรงขับที่สั่ง
2. กำหนดการเปลี่ยน epoch และการตัดประวัติที่ manual/disarm/cancel/fault ตลอดจนการตรวจเฟรมซ้ำและนาฬิกาผิด พร้อม deterministic tests ก่อนเชื่อมโมเดล นโยบายรับเพียงเจ็ดคำขอเดินเรือ ส่วน operator recovery ยังคงแยกจาก AI
3. พิจารณาโครงข่ายขนาดเล็กสำหรับ masked discrete-action learning เช่น DQN บน features ประวัติ แยก online/target network และ replay buffer แบบจำกัดขนาด ใช้ข้อมูลรางวัล/ผลปลายทางจากโลกจำลองเฉพาะฝึกและวัดผล ไม่ส่งข้อมูลนั้นเข้าตัวเลือกการกระทำ การสุ่มเริ่มต้นและการสำรวจต้องไม่ขยายสิทธิ์นอก mask
4. ทำสะพาน Node R2 ↔ ตัวเรียน Python ที่ใช้ schema ชัดเจนและไม่มีการเชื่อมอุปกรณ์ ส่งเวลาเดิม ไม่เปลี่ยนภาพเก่าให้สดเพราะรอ inference จำลอง การฝึกที่ใช้ virtual time ไม่ยืนยันความหน่วงจริงบน Pi ต้องรายงานขอบเขตนี้เสมอ
5. ก่อนเริ่มงานจริง แช่แข็ง source hash, architecture, normalization, reward, hyperparameters, งบฝึก, snapshot, เกณฑ์ validation และข้อมูลที่ใช้/ไม่ใช้ให้ครบ รวม RNG/replay/optimizer/target state ใน checkpoint ที่ resume ได้โดยไม่เริ่มจากศูนย์ หยุดเมื่อครบงบ ไม่วนเพิ่มรอบเพียงเพราะคะแนนต่ำ

## ข้อกำหนด protocol ที่จะต้องรักษา

- เลือกจาก validation เท่านั้น และใช้ test ภายหลังตามการทบทวนที่แยกออกมา ห้ามเปิด test เพื่อเลือก features หรือปรับตัวแปร
- ชุดที่สำรองไว้เดิมยังไม่เปิด: validation 38,000,000/38,500,000 และ test 40,000,000/40,500,000 ส่วนข้อมูลพัฒนา 36,000,000–36,000,013 และ 37,000,000–37,000,009 เปิดแล้ว ต้องเปิดเผยสถานะเมื่อใช้ต่อ
- ตัวอ้างอิงควรรวมกฎเดิม selector v1 และ selector v2 ภายใต้ plant/sensors/action mask เดียวกัน ไม่เลือกเพียงตัวอ้างอิงที่อ่อนในฉากเจาะจง
- คง R2 stress noise/dropout/gain ความเฉื่อย กระแสน้ำ ความหน่วง 600 มิลลิวินาที TTL 400 มิลลิวินาที และตัวกำกับเดิม การขอความช่วยเหลือไม่ตัด episode และไม่ลบการชนจากการลอยออกจากตัวหาร
- ใช้เกณฑ์วิจัยและเกณฑ์พร้อมใช้งานแยกกัน โดยยังไม่ลดเกณฑ์เดิมเพื่อให้โมเดลใหม่ผ่าน ผลจำลองไม่ใช่ผลอิสระจากสนามจริง
- ใช้เครื่องในระบบเดิมและ GPU ครั้งละงาน ไม่ใช้บริการที่มีค่าใช้จ่าย ตรวจพื้นที่ดิสก์ก่อนจัด replay/checkpoint และจำกัด log/ตัวอย่างดิบ ไม่คัดลอก dataset ขนาดใหญ่
- ไม่มีการส่งออกไปทับ policy บนเว็บหรือการสั่งมอเตอร์จริงก่อน compatibility review อุปกรณ์ และการสอบเทียบ

เมื่อ encoder และสะพานข้อมูลผ่านการตรวจ จึงกำหนด architecture/งบฝึกที่เหมาะสมและ protocol ฉบับจริงต่อไป การมีแผนนี้ไม่ใช่การยืนยันว่าจะผ่านเกณฑ์หรืออนุญาตให้เริ่มฝึกอัตโนมัติ
