# ตัวจำลองภารกิจรุ่นพัฒนา R2

`warirak-pool-mission-v4r2-dev` ปรับความหมายของข้อมูลระยะที่หายและหลักฐานความก้าวหน้า ก่อนกำหนดรอบฝึกใหม่ ซอร์สและรายงานของรุ่นพัฒนาก่อนหน้ายังอยู่ครบ รุ่นนี้ใช้ observation/request schema v2 และยังไม่มีนโยบาย AI ที่ฝึก ไม่มีตัวเชื่อมกับมอเตอร์หรือเว็บไซต์

เรียกจากรากโครงการ:

```sh
node ai/check_mission_simulation_r2.mjs
node --test tests/navigation-mission-r2.test.mjs
```

ตัวอย่างเป็นข้อมูลสังเคราะห์และกรณีที่กำหนดไว้สำหรับพัฒนา ไม่ใช่ validation/test อิสระหรือผลเรือจริง ข้อกำหนดอยู่ใน `navigation-mission-v4r2-contract.json` ซอร์สหลักคือ `navigation_mission_env_r2.mjs` และ `mission_range_evidence.mjs`

## ข้อมูลระยะที่หายกับข้อมูลที่ใช้ไม่ได้

เวลาhealth/controlปัจจุบันแยกจากเวลาจับข้อมูลระยะเดิมอย่างชัดเจน สถานะของข้อมูลระยะมีดังนี้:

| สถานะ | การจัดการ |
| --- | --- |
| `fresh` | มี packet ใหม่ที่ผ่านการตรวจแหล่ง หน่วย เวลา ลำดับ และค่า ยังต้องผ่านตัวกำกับทิศทาง/ระยะก่อนมีแรงขับ |
| `cached_wait` / `missing_wait` | ไม่มี packet ใหม่ ตัดแรงขับ ล้างคิวและคำขอเดิม แสดง `WAIT_RANGE_UPDATE` |
| `stale` | อายุเกิน300มิลลิวินาที ใช้สถานะfaultที่ค้างและต้องรีเซ็ต |
| `invalid` | อุปกรณ์แจ้งความผิดปกติ ข้อมูลผิดรูปแบบ แหล่ง/หน่วยไม่ตรง เวลาอนาคต ลำดับย้อนกลับ หรือpayloadขัดแย้ง ล้างค่าที่เก็บและใช้faultที่ค้างทันที |

ค่าครั้งล่าสุดที่เก็บไว้ยังมี `captured_at_ms` เดิม ไม่มีการเปลี่ยนเป็นเวลาปัจจุบัน **ใช้ตรวจย้อนหลังเท่านั้น ไม่ใช้อนุญาตแรงขับระหว่างรอข้อมูลใหม่** วิธีนี้ไม่ถือว่าทิศของรังสีวัดเดิมยังตรงกับหัวเรือหลังหมุนตัว และไม่เดาว่าพื้นที่ด้านหลังว่าง

เมื่อข้อมูลกลับมา คำขอเดิมไม่ฟื้นเอง ต้องมี packet ที่ผ่านการตรวจและคำขอใหม่ที่มีsequenceใหม่ การควบคุมเอง การปลดการทำงาน อายุคำสั่ง400มิลลิวินาที และการตรวจACKยังมีลำดับความสำคัญตามเดิม การตัดแรงขับยังปล่อยให้โลกจำลองคำนวณความเฉื่อยและกระแสน้ำ จึงไม่ยืนยันว่าเรือหยุดหรือไม่ชน

## หลักฐานความก้าวหน้าที่ยังไม่เพียงพอ

ความไม่แน่นอนความเร็วของstressยังเป็น0.008เมตร/วินาที และเกณฑ์ความเร็วต่ำยังเป็น0.015เมตร/วินาที ไม่มีการลดค่าความไม่แน่นอนเพื่อให้กรณีติดค้างผ่านเกณฑ์

เพิ่มการตรวจความก้าวหน้าจากตำแหน่งที่มีแหล่งข้อมูลอิสระในตัวจำลอง ใช้การเปลี่ยนตำแหน่งฉายตามทิศหัวเรือที่วัดเมื่อเริ่มช่วง พร้อมหักขอบเขตความไม่แน่นอนตำแหน่งและทิศทาง ต้องมีเวลาposeที่ไม่ซ้ำอย่างน้อยสามค่าและช่วงหลักฐานไม่น้อยกว่า300มิลลิวินาที จึงพิจารณาขอบล่างความก้าวหน้า0.08เมตรได้ ไม่แปลงแรงขับเป็นระยะหรือความเร็วที่อ้างว่าวัดได้

หากมีเวลาสะสมที่ACKเดินหน้าตรงกับคำสั่งครบสองวินาที แต่ยังยืนยันความก้าวหน้าอย่างเพียงพอไม่ได้ จะตัดแรงขับและค้างที่ `PROGRESS_UNCERTAIN` เพื่อขอให้ผู้ใช้ประเมิน นี่คือหลักฐานไม่เพียงพอ **ไม่ใช่การยืนยันว่าเรือหยุดนิ่งหรือมอเตอร์ติดขัด** หากposeขาดก็ไม่สร้างตำแหน่งทดแทน

ช่วงรอข้อมูลระยะใหม่พักการนับเวลาACKเดินหน้า แต่ไม่ล้างหลักฐานเดิมจนหลีกเลี่ยงการตรวจปัญหาได้ ส่วนSTOP, HOLD, การหมุนอยู่กับที่ การควบคุมเอง และการปลดการทำงานจะเริ่มช่วงตรวจใหม่ การติดค้างที่ผ่านเกณฑ์ความเร็วต่ำเดิมยังใช้ `RECOVERY_REQUIRED` แยกต่างหาก ทั้งสองสถานะเป็นการขอประเมินด้วยคน ยังไม่มีขั้นตอนขับแก้ติดค้างอัตโนมัติ

## ขอบเขตและงานก่อนฝึก

ตัวจำลองยังคงกระแสน้ำ แรงขับคลาดเคลื่อน ความหน่วง เสียงรบกวน และโอกาสข้อมูลหายของstressไว้ ข้อมูลpose/ความเร็วและรังสีรอบลำทั้งแปดเป็นเซนเซอร์จำลองเพิ่มเติมที่ยังไม่ได้สอบเทียบกับฮาร์ดแวร์ ขอบเขตความไม่แน่นอนและค่าขีดจำกัดในซอฟต์แวร์ไม่ใช่ความแม่นยำที่วัดจากอุปกรณ์จริง

กรณีพัฒนาที่ผ่านยังไม่แสดงอัตราเก็บสำเร็จ อัตราชน หรือความพร้อมต่อเนื่องในสนามnominal/stress กระแสน้ำอาจพาเรือที่มีปัญหาการขับเคลื่อนให้เคลื่อนหน้าได้ จึงใช้การตรวจความก้าวหน้าเพื่อบอกสภาพเชิงสังเกต ไม่อ้างว่าเป็นการวินิจฉัยมอเตอร์

งานถัดไปคือกำหนดสถานะ/โมเดลของผู้เรียนและbaselineที่ได้รับข้อมูลและตัวกำกับเดียวกัน แล้วแช่แข็งซอร์ส seed และเกณฑ์สัมบูรณ์/เปรียบเทียบก่อนฝึก เก็บกรณีfault การขอความช่วยเหลือ การหมดเวลา และความหน่วงเกินอายุคำสั่งไว้ในตัวหารผลประเมิน ห้ามตัดกรณีเหล่านี้ออกเพื่อให้คะแนนสูงขึ้น รุ่นนี้ยังเป็นงานพัฒนาในเครื่อง โมเดลตรวจจับและนโยบายที่เผยแพร่ยังคงเดิม
