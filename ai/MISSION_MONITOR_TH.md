# แยกคำสั่งหยุดออกจากการหยุดเคลื่อนที่

`warirak_ai.mission_monitor.MissionMonitor` เป็นส่วนตรวจสถานะเพิ่มเติมหลังพบตัวอย่างเรือจำลองลอยชนขณะใช้ STOP ทำหน้าที่แยกคำสั่ง ข้อมูลที่ตัวรับรายงานว่าใช้กับมอเตอร์ และหลักฐานการเคลื่อนที่ออกจากกัน

**ยังไม่มีตัวควบคุมรักษาตำแหน่งหรือกู้สถานการณ์ในโมดูลนี้** ไม่มี GPIO, serial หรือคำสั่งมอเตอร์ และยังไม่เชื่อมเป็นตัวควบคุมบนเว็บ ไม่ได้เปลี่ยนอัตราชนของ memory-v3 หรือทำให้ผ่านเกณฑ์ใช้งานจริง

## สถานะที่ตรวจได้

| สถานะ | ความหมาย |
|---|---|
| `MOTION_UNKNOWN` | ยังไม่มีหลักฐานความเร็วที่สด สอบเทียบแล้ว และมีความไม่แน่นอนเหมาะสม |
| `WAIT_STOP_ACK` / `WAIT_ACTUATOR_ACK` | ยังไม่มีรายงานการใช้คำสั่งจากตัวรับที่สอดคล้องกับช่วงคำสั่งนี้ |
| `STOPPING_OBSERVED` | มีคำขอหยุด แต่หลักฐานยังไม่พอให้ยืนยันว่าหยุดเคลื่อนที่ |
| `STOPPED_OBSERVED` | มีหลักฐานหลายตัวอย่างว่าความเร็วต่ำในช่วงที่ตรวจ ยังไม่รับรองการรักษาตำแหน่งต่อไป |
| `HOLD_REQUIRED` | ยังเคลื่อนที่ต่อเนื่องหลังตัวรับรายงานแรงขับศูนย์ หรือมีคำขอรักษาตำแหน่ง ต้องใช้ตัวควบคุมที่ยังไม่มีหรือให้ผู้ใช้ช่วย |
| `RECOVERY_REQUIRED` | มีรายงานใช้แรงขับ แต่ความเร็วต่ำต่อเนื่อง เป็นเหตุให้ตรวจการติดค้าง ไม่สั่งถอยหรือหมุนเอง |
| `FAULT_STOP` | เซนเซอร์ แบตเตอรี่ ระยะปลอดภัย ลำดับคำสั่ง หรือนาฬิกามีปัญหา |
| `MANUAL_OVERRIDE` / `DISARMED` | ให้ความสำคัญกับการควบคุมเองหรือการปิดช่องทางอัตโนมัติ |

คำขอช่วยเหลือและข้อผิดพลาดค้างไว้จนมีการเรียก `reset()` อย่างชัดเจนพร้อมข้อมูลยืนยันว่า disarmed และเป็นข้อมูลสด การที่ความเร็วกลับเป็นศูนย์หรือสิ่งกีดขวางหายไปไม่ล้างสถานะค้างโดยอัตโนมัติ

## หลักฐานการเคลื่อนที่

ข้อมูล `motion` ต้องใช้ schema `warirak.motion-estimate.v1` มีเวลา Unix milliseconds ความเร็ว `vx_mps`/`vy_mps` ในกรอบ `pool_fixed` หรือ `earth_fixed`, หน่วย `m/s`, ธง `calibrated=true`, ค่าความเชื่อมั่น และ `speed_std_mps` ที่บอกความไม่แน่นอน

ใช้ `source="simulation"` กับ `method="simulation_truth"` เฉพาะการทดลองสังเคราะห์ ส่วนบันทึกจริงใช้ `source="measured"` กับแหล่งที่ผ่านการตรวจ เช่น external tracking, GNSS velocity หรือ visual odometry ที่สอบเทียบแล้ว การรับรูปแบบข้อมูลนี้ไม่ได้หมายความว่าโครงงานมีอุปกรณ์เหล่านี้แล้ว

โมดูลไม่คำนวณความเร็วจริงจากค่าคำสั่งมอเตอร์ ไม่แปลงพิกเซลต่อวินาทีเป็นเมตรต่อวินาทีเอง และไม่ใช้ข้อมูลเก่า ความเชื่อมั่นต่ำ หน่วยผิด หรือนาฬิกาย้อนเป็นหลักฐานว่าหยุดอยู่ ภาพ/ค่าประเมินเดิมที่ส่งซ้ำไม่เพิ่มจำนวนหลักฐาน

`actuator_feedback` ใช้ schema `warirak.actuator-feedback.v1` มีเวลา `applied_sequence` และค่าซ้าย/ขวาที่ตัวรับรายงานว่าใช้จริง รูปแบบบันทึกจริงต้องระบุ `source="controller_feedback"` ส่วนตัวอย่างสังเคราะห์ใช้ `simulation` ห้ามใช้ข้อมูลสังเคราะห์แทนหลักฐานจริง รายงานนี้เป็นหลักฐานสถานะตัวรับ ยังไม่ใช่การวัดแรงขับทางกล

## ขอบเขตของเวลาและความเร็ว

ค่าเริ่มต้นสำหรับทดสอบซอฟต์แวร์คืออายุข้อมูลไม่เกิน500มิลลิวินาที หลักฐานต่อเนื่อง600มิลลิวินาทีอย่างน้อย3ตัวอย่าง และตรวจความเร็วต่ำต่อเนื่อง2000มิลลิวินาทีสำหรับเหตุอาจติดค้าง มีช่วงความไม่แน่นอนระหว่าง stationary/moving แทนการบังคับทุกค่าให้เป็นสองกลุ่ม

ค่าเหล่านี้ **ยังไม่สอบเทียบกับเรือ กล้อง หรือมอเตอร์จริง** การตั้ง `calibrated=true` ในข้อความทดสอบไม่ใช่หลักฐานการสอบเทียบ การใช้งานจริงต้องตรวจแหล่งข้อมูล นาฬิกา ความไม่แน่นอน และระยะตอบสนองก่อน

ผลทุกครั้งมี `control_enabled=false`, `station_keeping_verified=false` และระบุว่าตัวควบคุม HOLD/RECOVERY ยังไม่มี `proposal_allowed` เป็นเพียงสถานะแนะนำในซอฟต์แวร์ ไม่ข้ามข้อจำกัด watchdog/manual override/ระยะปลอดภัยของ `shadow_control`

## ลองกรณีสังเคราะห์

จากโฟลเดอร์ `ai`:

```sh
python examples/check_mission_monitor.py
```

ตรวจห้ากรณีที่กำหนดไว้: ไม่มีข้อมูลการเคลื่อนที่ หยุดตามหลักฐาน ยังเคลื่อนที่หลังคำขอหยุด อาจติดค้าง และไม่มี ACK จากตัวรับ ไม่ฝึกนโยบายใหม่ ไม่รันวิดีโอจริง ไม่วัดอัตราชน และไม่ต่ออุปกรณ์
