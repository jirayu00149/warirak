# ส่วนบันทึกประวัติสำหรับการศึกษาการหลบล่วงหน้า

เพิ่ม `ProactiveSidecar` และตัวหุ้ม `ProactiveSidecarR2` เพื่อเก็บข้อมูลต้นฉบับ ประวัติ features คำขอ และคำสั่งที่ตัวจำลองออกจริงแบบจำกัดขนาด ใช้ schema `warirak.proactive-sidecar.v1` และ `warirak.proactive-sidecar-r2-step.v1` ข้อกำหนดอยู่ใน `proactive-sidecar-contract.json`

ส่วนนี้ต่อจาก observer ที่ตรวจเสร็จแล้วใน `PROACTIVE_OBSERVATION_TH.md` ยังไม่มีตัวเลือกการหลบหรือนโยบายที่ฝึกใหม่ ไม่มีการเปิด validation/test หรือเปลี่ยนนโยบายบนเว็บ

## ข้อมูลที่เก็บและเวลาเดิม

ค่าปริยายเก็บแพ็กเก็ตเต็ม 12 รายการ หน้าต่าง features ที่ใช้ต่อได้ 12 รายการ ทะเบียน issued control 16 รายการ และเหตุการณ์ 32 รายการ จำกัดแพ็กเก็ต/transition แต่ละรายการไว้ที่ 32 KiB และคำขอ/issued control ที่ 4 KiB สำเนาที่คืนให้ผู้เรียกแยกจากข้อมูลภายใน จึงแก้ย้อนหลังผ่านผลลัพธ์ที่ได้รับไม่ได้

แพ็กเก็ตเต็มที่รับไว้ยังมี target สถานะ armed/manual แบตเตอรี่ mission pose motion และเวลาเดิม ส่วนประวัติที่จัดไว้สำหรับผู้เรียนมีเฉพาะ features และข้อมูลคำขอที่อนุญาต ข้อมูลพิกัดโลกใน diagnostic ยังแยกจาก features

ตัวจำลอง R2 ไม่มีหมายเลขแพ็กเก็ตสังเกตอิสระ ส่วนบันทึกจึงตรวจ timestamp เดิมร่วมกับ digest ของแพ็กเก็ตเต็มที่จัดลำดับ key แบบแน่นอน เลข record sequence ที่สร้างขึ้นเป็นเพียงลำดับการบันทึกในเครื่อง ไม่ใช่หมายเลขเฟรมกล้องหรืออุปกรณ์

- แพ็กเก็ตเหมือนเดิมและเวลาเดิมไม่เพิ่มประวัติ ไม่สร้าง decision context ใหม่ และไม่เปลี่ยนเวลาเดิมให้สดขึ้น
- ข้อมูลต่างกันที่ timestamp เดียวกัน เวลาไหลย้อน หรือ sequence ระยะถอยหลัง/ขัดแย้ง ทำให้ส่วนบันทึกเข้าสถานะ fault ที่ค้างไว้ พร้อมล้างหน้าต่าง features และทะเบียนคำสั่งที่ใช้อยู่
- pose/motion ที่คง timestamp และเนื้อหาเดิมไม่เป็นหลักฐานการวัดใหม่ ระยะ cached ยังเป็น unknown แม้เรือหมุน heading แล้ว
- แพ็กเก็ตที่ถูกต้อง ณ เวลาต้นทางแต่ล่าช้าจนเก่าเมื่อมาถึง ยังคงเก็บต้นฉบับได้ โดย features ที่เก่าเป็น unknown และไม่มี decision context

ขณะ fault ที่ค้างอยู่ หรือเมื่อแพ็กเก็ตผิดรูปแบบ/เกินขนาด จะเก็บ metadata เหตุการณ์แทนแพ็กเก็ตเต็ม จึงไม่อ้างว่าส่วนบันทึกนี้สร้างประวัติการฝึกหรือข้อมูลที่ปฏิเสธได้ครบทุกเฟรม

## คำขอและคำสั่งที่ออกจริง

เก็บ `request_sequence` ของคำขอแยกจาก `control_sequence` ของ issued control แล้วให้ observer จับคู่ ACK กับทะเบียนคำสั่งเดิม การมีคำขอใหม่ไม่เปลี่ยนหมายเลข ACK เก่าให้ตรงกัน

คำขอการเดินเรือของ AI มีเจ็ดรายการเดิม ส่วน RECOVERY_REQUEST บันทึกผ่าน owner แบบ operator อย่างชัดเจน การแยก owner เป็นข้อกำหนดซอฟต์แวร์วิจัย ยังไม่ใช่ระบบยืนยันตัวตนของผู้ใช้

เมื่อผู้เรียกส่ง `null` จะเก็บ `null` และส่งต่อให้ตัวจำลองตามเดิม ไม่มีการสร้างคำขอซ้ำหรือขยาย TTL ตัวจำลองอาจยังใช้คำขอก่อนหน้าที่ไม่หมดอายุตามพฤติกรรมเดิม และ watchdog เดิมจะเป็นผู้ตรวจเวลาหมดอายุ

คำขอที่ไม่ถูกต้องยังบันทึกพร้อมผล transition ที่เกิดขึ้นได้ หากแพ็กเก็ตสังเกตก่อนหน้านั้นรับไว้สำเร็จ จึงตรวจได้ทั้งสิ่งที่ผู้เรียกเสนอและสิ่งที่ตัวกำกับของตัวจำลองยอมใช้จริง

## การยกเลิกและการรีเซ็ต

manual override, disarm หรือบริบทที่ไม่พร้อม ทำให้ประวัติการตัดสินใจและทะเบียนที่ใช้อยู่ถูกล้าง ข้อมูล diagnostic ที่รับไว้แล้วคงอยู่ภายในขอบเขตจำนวนที่กำหนด

`cancel()` ยกเลิกเฉพาะบริบทของส่วนบันทึก โดยสร้างคำสั่งเป็นศูนย์รายการ เมธอดนี้ไม่มีหน้าที่ส่ง STOP ไปยังเรือ ผู้ควบคุมจริงในอนาคตยังต้องส่ง STOP ผ่านตัวกำกับและตัวรับคำสั่งที่เหมาะสม การกลับมาบันทึกบริบทหลัง cancel ต้องมีแพ็กเก็ตใหม่และคำขอใหม่ที่ sequence เพิ่มขึ้น ACK หรือ issued control เก่าไม่เติมทะเบียนกลับโดยอัตโนมัติ

fault ของส่วนบันทึกต้องรีเซ็ตอย่างชัดเจนด้วยแพ็กเก็ต disarmed ที่สดและใหม่กว่าเดิม การรีเซ็ตคง high-water marks ของเวลา/sequence ไว้ เมื่อเริ่ม episode ใหม่หรืออุปกรณ์เริ่ม sequence ใหม่ ต้องสร้าง stream ที่มีเจ้าของใหม่อย่างชัดเจน ไม่เลื่อนนาฬิกาย้อนเพื่อให้ข้อมูลผ่าน

## ตัวหุ้มตัวจำลอง

`ProactiveSidecarR2` รับ instance R2 ที่เปิด record และเป็นของผู้เรียก เก็บข้อมูลก่อนแต่ละ `step` บันทึกคำขอ แล้วให้ R2 ประมวลผลคำขอเดิมโดยตรง จากนั้นคัดลอก issued/applied control และผลการเคลื่อนที่จาก trace ที่ตัวจำลองสร้างจริง ตัวหุ้มใช้ trace นั้นและเหลือรายการล่าสุดไว้หนึ่งรายการ ผู้ใช้ที่ต้องการ trace เต็มควรใช้บันทึกแบบจำกัดขนาดที่ตัวหุ้มเก็บไว้ หรือใช้ตัวจำลองแยก

fault ของส่วนบันทึกไม่แทรกแซงตัวควบคุมของ R2 และไม่ทำให้เกิดคำสั่งหยุดทางกายภาพ ตัวกำกับระยะปลอดภัย manual override ACK และ watchdog ของ R2 ยังคงเป็นผู้ตัดสินคำสั่งที่ใช้จริง ตัวหุ้มไม่มี loop จับเวลา และเรียกใช้ได้เฉพาะกับตัวจำลอง ไม่เชื่อม serial/GPIO หรืออุปกรณ์

```js
import {ProactiveSidecarR2} from './proactive_sidecar_r2.mjs';

const recorder = new ProactiveSidecarR2(ownedR2Environment);
recorder.step(originalCallerRequest); // หรือ null ตามคำขอเดิมของผู้เรียก
const history = recorder.sidecar.decisionWindow();
const diagnostic = recorder.sidecar.records();
```

## ผลตรวจและงานถัดไป

การทดสอบเฉพาะส่วนใหม่ผ่าน 26 รายการ ครอบคลุมข้อมูลซ้ำ/ขัดแย้ง เวลาและ sequence ถอยหลัง ข้อมูลเก่าระหว่างส่ง ระยะ cached การวัด motion ซ้ำ ขอบเขตประวัติ ACK คำขอยกเลิก การรีเซ็ต และการแยก owner รวมถึงการเทียบ snapshot ของตัวจำลองที่มี/ไม่มีตัวหุ้มภายใต้คำขอชุดเดียวกัน

กรณี manual/disarm ยังให้แรงขับเป็นศูนย์พร้อมการลอยตามน้ำ กรณีความหน่วง 600 มิลลิวินาทียังคงควบคุมไม่พร้อมภายใต้ TTL 400 มิลลิวินาที ไม่ขยายอายุคำสั่งหรือลดกระแสน้ำเพื่อให้ผลดูดีขึ้น การตรวจนี้เป็น deterministic software/fixture tests ไม่ใช่อัตราความสำเร็จของนโยบายใหม่หรือผลเรือจริง

ขั้นถัดไปคือออกแบบตัวเสนอการหลบล่วงหน้าจาก features/ประวัติที่มีอยู่ โดยคง action mask และตัวกำกับ R2 ก่อนกำหนดกรณีพัฒนาแบบจำกัดพร้อมแผนและ hash ล่วงหน้า เมื่อมีหลักฐานจากกรณีพัฒนาแล้วจึงพิจารณา schema นโยบาย วิธีเรียนรู้ และ protocol ใหม่ ยังไม่เริ่มฝึกเพียงเพราะส่วนบันทึกเสร็จ และไม่เปิด test เพื่อเลือกสมมติฐาน
